# 통역 전 구간 벤치마크

음성 파일을 마이크 대신 앱에 넣어, 실제 앱의 통역 흐름 전체(스트리밍 인식 → 구간 끊기 → 2단계 인식 → 번역)를
실제 말하는 속도로 돌리고 잰다. 번역 벤치마크(`bench/`)와 음성 인식 벤치마크(`bench/stt/`)는 단계를 따로 재지만,
여기서는 듣는 사람이 느끼는 지연("말이 끝난 뒤 번역이 다 나올 때까지")과, 설정을 바꿨을 때 전체가 어떻게 달라지는지를 본다.

같은 음성을 설정만 바꿔 두 번 돌려 비교하는 용도다.

## 넣을 음성

- **만든 음성**: 음성 인식 벤치마크의 시험 발화를 무음을 사이에 두고 이어 붙인 것. 발화마다 위치와 기준 문장을 알고 있어
  지연과 오류율을 모두 잴 수 있다. 대화 문장 세트는 기준 한국어 번역도 있다.
- **실제 녹음**: 디버그 빌드의 화면 위쪽 **음성 저장**을 켜고 통역하면, 폰 마이크로 들은 음성과 그때의 통역 기록이
  폰에 남는다. 가져와서 그대로 다시 넣을 수 있다. 기준 문장이 없으므로 지연("확정 → 번역 끝")과 결과 문장만 비교하고,
  녹음 옆에 받아 적은 영어를 `<이름>.ref.txt` 로 두면 오류율도 잰다.

"내 차례"로 듣기를 멈춘 동안의 소리는 녹음에 남기지 않고 무음으로 채운다.

## 돌리는 법

폰을 USB로 연결하고 잠금을 푼 뒤 (만든 음성은 먼저 `python3 bench/stt/prepare_audio.py` 가 되어 있어야 한다):

```bash
python3 bench/e2e/build_stream.py --per-set 6
```

```bash
bench/e2e/run.sh
```

```bash
python3 bench/e2e/score.py
```

- `build_stream.py` 는 `bench/build/e2e/stream.wav` 와 발화 위치·기준 문장(`stream.ref.jsonl`)을 만든다. 세트마다 6개면 약 4분이다.
- `run.sh` 는 디버그 빌드를 설치하고, 음성을 `debug-input.wav` 로, 설정을 `debug-config.json` 으로 넣은 뒤 앱을 띄워 통역을
  시작시킨다. 음성 길이만큼 걸리고, 끝나면 통역 기록을 `bench/results/e2e-<시각>/` 으로 가져온 다음 넣었던 파일을 지운다.
- 설정은 저장소의 `remote/config.json` 을 쓴다 (폰이 받아 둔 원격 설정이 아니다). 다른 설정과 비교하려면:

```bash
CONFIG=내설정.json LABEL=이름 bench/e2e/run.sh
```

```bash
python3 bench/e2e/score.py bench/results/e2e-...-기준 bench/results/e2e-...-이름
```

실제 녹음을 가져와 다시 돌리기:

```bash
bench/e2e/pull.sh
```

```bash
bench/e2e/run.sh bench/recordings/20261117-193000.wav
```

`bench/recordings/` 에는 실제 대화가 담기므로 저장소에 올리지 않는다(.gitignore). 폰의 녹음은 `bench/e2e/pull.sh --delete` 로 지운다.

## 통역 기록 (`<이름>.jsonl`)

한 줄에 하나씩, `ms` 는 음성이 시작된 뒤로 흐른 시간이다 (음성 파일 속 위치와 같은 기준).

- `session`: 시작 시각, 입력(mic / file), 앱 버전, 음성 인식 설정
- `utterance`: 구간 하나. `finalMs` 구간이 확정된 시각, `ms` 번역이 끝난 시각, `audioSec` 구간 음성 길이,
  `streaming` 스트리밍 인식 문장, `english` 번역에 넘긴 문장(2단계 인식), `korean` 번역, `speculated` 미리 번역을 이어 썼는지
- `pause`: "내 차례"를 켜고 끈 시각
- `end`: 통역이 끝난 시각

## 읽을 때 주의할 점

- 실제 속도로 한 번 돌린 결과다. 폰의 상태(발열, 다른 앱)에 따라 번역 시간이 수백 ms 씩 달라질 수 있으니, 작은 차이는 두 번 이상 돌려 확인한다.
- 만든 음성은 발화 사이가 1.2~2.5초 무음으로 깨끗하게 떨어져 있다. 실제 대화는 말이 겹치고 주변 소리가 있다.
- 파일 입력은 마이크와 마이크 처리(잡음 억제 등)를 거치지 않는다. 그 영향은 실제 녹음을 다시 넣어야 볼 수 있다.
- "말 끝"은 기준 발화 음성의 끝이다. 공개 세트의 발화는 끝에 조금 여유가 있어 실제 말 끝보다 늦을 수 있다(두 실행에 똑같이 작용한다).
- chrF2 는 기준 번역이 있는 발화(세트마다 6개면 6문장)만 보므로 흔들림이 크다. 번역 품질 자체는 `bench/RESULTS.md` 를 본다.
- 답변 제안은 재지 않는다.
